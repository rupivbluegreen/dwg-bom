dwg-bom

Turns an AutoCAD DWG drawing into a draft bill of materials — the way an estimator would build one, minus the hours of reading sheets by hand. It never invents a quantity, and nothing about your drawing leaves your computer.

The problem

Steel and railing drawings specify every material in notes and leader callouts, but nobody wants to transcribe 40 sheets of them into a spreadsheet by hand — and any script that tries risks quietly making up a size or a quantity that was never on the drawing.

What estimators do today

Open every sheet, read every note and leader, and manually copy materials, sizes and callouts into a spreadsheet — slow, and easy to miss something on a dense detail sheet.

What dwg-bom does instead

Reads the DWG directly, classifies every note it can with deterministic rules, asks a local model only about what's left, and hands back a draft with every line traceable back to the exact note it came from.

The pipeline

Seven stages, each one plain data in and plain data out, so any stage can be inspected, re-run or replaced on its own.

1

Convert

dwgbom/convert.py · LibreDWG dwg2dxf

DWG is a closed binary format, so nothing downstream reads it directly. LibreDWG converts it to DXF, the open text form, cached in out/dxf/.

2

Extract

dwgbom/extract.py · ezdxf

Walks model space, every layout and every block definition (following nested blocks) and records notes, dimensions, block inserts, linework lengths, viewport scales and the title block — each tagged with its DWG entity handle.

3

Rules

dwgbom/rules.py · regex + arithmetic

Deterministic recognisers for steel (W/C/L shapes, HSS, OWSJ, plate), railing, cable, fasteners, checker plate, wood framing and roofing — plus a check on every imperial/metric pair, which is what catches sheet A-05's mislabelled 3/4″ O.S.B.

4

Local LLMoptional

dwgbom/llm.py · Ollama or any OpenAI-compatible server

Sees only the handful of notes the rules could not place — on a typical detail sheet, 2 notes out of 38. Its one job is to classify and name each note in plain English; it is explicitly told never to add a size, grade or quantity.

5

Guard

dwgbom/llm.py: guard()

Checks every model answer against the original note: the id must be one that was sent, and every number in the answer must appear in the note's own text. Anything that fails is kept but marked unverified for a person to check.

6

Assemble

dwgbom/bom.py

Merges duplicate callouts into one line, looks up steel mass per metre from the designation, and infers a mass when a note and a nearby profile block agree on exactly one match. Every row gets a status: needs quantity, needs mass/m, FIX unit error, and so on.

7

Export

dwgbom/export.py · openpyxl

Writes a workbook with BOM, Flags, Notes and Drawing info sheets, plus the same data as JSON. Quantity and length cells are highlighted yellow for a person to fill in; total length and mass are live formulas.

Where the AI is — and isn't

Six of the seven stages are plain, deterministic Python that run on every drawing. Exactly one is a model, and it only ever sees what the other six couldn't already place.

On sheet A-05 that's 2 notes out of 38 — and even those 2 pass through the Guard (stage 5, also plain Python) before reaching the BOM. Run with --no-llm and stages 1–3, 6 and 7 alone still produce a full draft; leftover notes are just labelled unmatched instead of classified.

Quantities are never invented

This is the rule the whole design serves. A drawing note tells you what something is; it almost never tells you how many.

How the guard actually works

  • Code counts, the model reads. Every number that reaches the BOM by arithmetic — mass per metre, block counts, linework length — is computed in plain Python, never guessed by the model.
  • The LLM only classifies. Stage 4 receives leftover notes and is instructed to use only the words already on them. It cannot add a size, grade or count that wasn't already written on the sheet.
  • Every model answer is re-checked. Stage 5 rejects any id the model wasn't sent, and flags unverified any answer containing a number that isn't in the original note — for example if the model turns W12 into W12x26, the row keeps W12 and a warning.
  • "Callouts on sheet" is evidence, not quantity. It counts how many times a note points at an item — useful context, explicitly labelled as not a count of physical pieces. The Qty and Length cells stay empty, highlighted yellow, until an estimator fills them in.
  • Unit mismatches block the row. Every imperial value with a metric value in brackets is checked; a mismatch is an error, not a warning, and holds up that row's status until it's fixed.

Runs entirely on your machine

No part of this pipeline calls out to a cloud API. The DWG, its notes, and the draft BOM never leave the computer they were opened on.

☐

LibreDWG

GPL-3, installed with brew install libredwg. Called as a separate program, so it doesn't affect this project's own MIT licence — see NOTICE.md.

◉

Ollama

MIT-licensed local model server. Runs Qwen3.8-27B (Apache 2.0) fully offline for the one stage that touches language.

⌂

Your files, your disk

Uploads and generated files sit in a local temp folder and are deleted after download or a short timeout — nothing is kept longer than it needs to be.

Or from the command line

The web UI calls the exact same run_one() function as the CLI — pick whichever fits how you work.

cd dwg-bom
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

python run.py "path/to/drawing.dwg"
open out/*_BOM.xlsx
